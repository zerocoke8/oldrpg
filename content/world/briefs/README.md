# 브리프 — 지역 하나를 만들기 위해 사람이 쓰는 것

```
npm run author -- b3 --dry-run    # 지도만 그려 본다. 모델을 부르지 않는다
npm run author -- b3              # 개요 + 씨앗을 만들어 regions/b3.json 에 쓴다
```

브리프는 **입력**이다. 서버는 브리프를 읽지 않는다 — 읽는 것은
`content/world/regions/*.json` 뿐이다.

## 분업

| | 누가 | 왜 |
|---|---|---|
| 배치 (타일) | 결정론적 생성기 (`server/engine/layout.ts`) | 맵 구조는 세계의 진실이다 (규칙 1). 모델이 만들면 연결성도, 출구가 벽 자리라는 성질도, `'E'` 와 적 배치의 짝도 아무것도 보장되지 않는다 |
| 씨앗 (문장) | LLM (`server/narration/author.ts`) | 이게 모델이 잘하는 일이다 |
| 적·NPC·`sensitive` | 사람 | 진행과 난이도의 결정이다. 도구는 손대지 않는다 |
| 문 | 사람이 **한쪽만** 적고, 도구가 양쪽에 쓴다 | 어디에 붙는지는 사람의 결정이지만, 짝을 손으로 맞추면 좌표 하나가 어긋난다 |
| 검토·커밋 | 사람 | 커밋되는 순간 씨앗은 불변이 된다 (규칙 3) |

**저작 시점의 모델 호출은 규칙 1·2와 부딪히지 않는다.** 그 규칙들은 런타임의
규칙이다 — 모델 출력이 살아 있는 게임 상태를 바꾸는 경로가 없어야 한다는 것.
여기서 나온 문장은 파일로 나가 사람의 리뷰를 거쳐 커밋된다. 런타임에는 이
경로가 아예 존재하지 않고, `.eslintrc.cjs` 가 서버가 `narration/author` 를
import 하는 것을 빌드 에러로 막는다.

## 파일

```json
{
  "name": "물에 잠긴 계단",
  "theme": "지하 2층으로 내려가는 나선 계단이 중간에서 무너져...",
  "landmarks": ["무너진 나선 계단", "물에 뜬 책장"],
  "rooms": 24,
  "layoutSeed": 20260906,
  "loopChance": 0.14,
  "tiles": null,
  "overview": null,
  "doors": [
    { "at": "5,2", "dir": "east", "to": { "region": "d6town", "x": 1, "y": 6 } }
  ]
}
```

## `sensitive` 를 선언한 방의 씨앗 규칙

**그 플래그의 두 값 모두에서 참인 문장이어야 한다.**

씨앗은 불변이고(규칙 3), 플래그가 켜지면 무드 문장이 **뒤에 붙을 뿐 씨앗을
대체하지 않는다.** 그래서 씨앗이 진행 중인 상태를 현재형으로 못 박아 두면,
그 방은 플레이어가 무엇을 하든 이전 상태를 계속 주장한다.

실제로 그랬던 것:

```
ue001 8,7  "봉인된 격리문. 잠금 장치가 안쪽에서 걸려 있다"
           ← journal_recovered 가 켜지면 바로 그 문이 열리는데 여전히 잠겼다고 말한다
ue001b 2,5 "증식이 멈추지 않은 중심. …계속 자라고 있었다"
           ← proliferant_slain 이 켜진 뒤에는 거짓이다
```

고친 뒤:

```
ue001 8,7  "격리문. 잠금 장치가 바깥이 아니라 안쪽에 달려 있다"
ue001b 2,5 "증식의 중심. 벽과 바닥이 여기서부터 자라난 것이 눈으로 보인다"
```

둘 다 **구조를 말하지 사건을 말하지 않는다.** 사건은 무드가 말한다.

## 무드 문장의 규칙 — '지금 없다' 가 아니라 '그런 일이 있었다'

`prompts/moods/<플래그>.md` 는 사건을 말하는 자리다. 그런데 그 사건의 주인공이
**돌아오는 적**이면(`respawnMs` 가 있는 적), 무드가 "그것이 지금 없다" 를 쓰는
순간 그 문장은 적이 돌아온 뒤 거짓이 된다. 플래그는 한 방향이라 되돌아가지
않으므로, 방은 영영 "사라진 뒤" 를 말하면서 살아 있는 적과 마주 본다.

플래그와 리스폰은 다른 축이다:

```
플래그      세계가 영구히 바뀌었다   — 한 방향. 되돌아가지 않는다
respawnMs   그 적이 지금 있는가      — 왕복한다
```

그래서 무드는 **한 방향인 쪽만** 말해야 한다. 실제로 그랬던 것:

```
proliferant_slain   "증식하던 어둠의 중심이 방금 끊겼다"
                    ← 증식체가 5분 뒤 돌아오면 거짓이다
```

고친 뒤:

```
proliferant_slain   "증식체가 한 번 쓰러진 적이 있는 자리다. 자라던 것이 그때
                     멈췄고, 그 뒤로 다시 자라기 시작했더라도 '한 번 멈춘 적이
                     있다' 는 사실은 남아 있다"
```

`방금`·`직후`·`더 이상`처럼 **지금을 못 박는 말**이 신호다. 기계가 볼 수 없는
규칙이라 여기 있다 — 씨앗 규칙과 같은 이유로, 사람이 리뷰에서 잡는다.

## `overview` — 비워 두지 말 것

개요는 방 씨앗을 쓸 때 참고할 **공통의 사실**이다. 이걸 먼저 만드는 이유는
방마다 따로 물으면 서로를 모르는 50개의 문장이 나오기 때문이다.

한때 여섯 브리프가 **전부 `null`** 이었다. 지금 세계는 `--layout-only` + 손으로
쓴 씨앗이라 개요가 한 번도 생성된 적이 없었고, 그 상태로 누가 방을 더 뚫으면
새 방들은 기존 방들과 서로를 모르는 문장이 된다.

채워져 있으면 도구가 모델을 부르지 않는다. **이미 커밋된 씨앗에서 거꾸로
요약해 적어 넣어도 된다** — 씨앗을 안 건드리므로 비용이 0이다.
`test/world.ts` 가 지역마다 개요가 있는지 본다.

## `doors` — 세계의 어디에 붙는가

**한쪽만 적는다.** 반대편 짝(`d6town` 의 `1,6 west -> 이 지역 5,2`)은 도구가
만들어 저쪽 파일에 써 넣는다.

왜 이렇게 하는가: 어디에 붙는지는 진행의 결정이라 사람의 입력이 맞다. 그런데
그 입력을 **두 파일에 나눠** 손으로 적게 하면 좌표 하나가 어긋나고, 그건
부팅에서야 잡힌다 — 그때는 이미 두 파일을 열어 놓고 어느 쪽이 맞는지 되짚어야
한다. 한 번 적고 도구가 써 내려가면 어긋날 자리가 없다.

도구가 **모델을 부르기 전에** 본다 (틀리면 돈이 안 나간다):

- `at` 이 걸을 수 있는 칸인가
- 그 `dir` 쪽이 **벽**인가 — 걸어갈 수 있는 칸을 가리키면 같은 키 입력에 두
  가지 뜻이 생긴다
- 저쪽 지역이 실재하고, `to` 가 걸을 수 있는 칸이고, 그 반대 방향도 벽인가
  (짝을 놓을 자리)

`requires` 와 `minRank` 도 여기 적으면 양쪽에 같이 들어간다.

**문이 없는 새 지역은 부팅 검증을 통과하지 못한다** — 아무도 갈 수 없는 지역은
세계가 아니다 (`assertReachable`). 그래서 `doors` 는 사실상 필수다.

**문의 원본은 브리프다.** 지역 파일의 `exits` 를 지우고 도구를 다시 돌리면
되살아난다. 없애려면 브리프에서 지운다.

| 필드 | | |
|---|---|---|
| `name` | 표시 이름 | 상태창에 나온다 |
| `theme` | 이 장소가 무엇인가 | **사람이 쓰는 유일한 창작.** 나머지는 전부 여기서 파생된다 |
| `landmarks` | 반드시 있어야 하는 것들 | 개요가 이걸 중심으로 짜인다 |
| `rooms` | 목표 방 수 | 50방쯤을 권한다 (`content/world/README.md` 의 "지역 크기") |
| `layoutSeed` | 배치 생성기의 시드 | 같은 시드는 같은 지도. **지도가 어디서 왔는지가 커밋 안에 남는다** |
| `loopChance` | 고리가 생길 확률 | `0` 이면 막다른 길 투성이의 나무 미로. `0.1`~`0.2` 가 걷기 좋다 |
| `tiles` | 손으로 그린 격자 | 적으면 생성기를 쓰지 않는다. 마을·보스방처럼 모양이 중요한 곳 |
| `overview` | 도구가 적는다 | 한 번 만들면 다시 만들지 않는다 — 방을 나중에 더 뚫어도 같은 장소여야 한다 |

## 순서

1. **브리프를 쓴다.** `theme` 과 `landmarks` 가 전부다.
2. **`--dry-run` 으로 지도를 본다.** 마음에 안 들면 `layoutSeed` 를 바꿔 다시.
   모델을 한 번도 부르지 않으므로 공짜다.
3. **`npm run author -- <id>`.** 개요 1회 + 열 칸씩 묶어 씨앗을 채운다.
   묶음마다 파일에 쓰므로 중간에 죽어도 이어서 돌리면 된다.
4. **읽는다.** 마음에 안 드는 씨앗은 **지운다.** 다시 돌리면 그 칸만 다시 짓는다.
   고쳐 써도 된다 — 도구는 이미 있는 씨앗을 절대 덮어쓰지 않는다.
5. **적·NPC·문·`sensitive` 를 손으로 붙인다.** 좌표는 이제 지도에 보인다.
   문을 붙였으면 반대편 지역에도 짝을 붙인다 (없으면 부팅이 거절한다).
   NPC 의 `persona` 와 `topic.seed` 도 씨앗이라 커밋되면 불변이다.
6. **`npm start` 로 부팅해 본다.** 틀린 것은 서버가 뜨기 전에 말해 준다.
7. **커밋한다.** 여기서부터 씨앗은 불변이다.

## 덮어쓰지 않는다

도구는 **빈 것만 채운다.** 씨앗도, 타일도, 개요도.

씨앗을 한 글자 고치면 `seed_id` 가 바뀌어 그 방의 생성된 텍스트가 전부 캐시
미스가 된다. 타일을 다시 만들면 좌표가 통째로 밀려서 이미 쓴 씨앗이 전혀 다른
방에 붙는다 — 조용히 세계가 뒤섞인다.

다시 짓고 싶으면 사람이 그 줄을 지우고 도구를 다시 돌린다. **지우는 것은 사람의
결정이어야 한다.**
